# Дискретно — подготовка к коллоквиуму

Русскоязычное приложение на React + TypeScript + Vite, Tailwind CSS и KaTeX. Основной курс работает локально без входа. Для необязательной синхронизации между устройствами добавлены Supabase Auth и база прогресса; сетевых шрифтов нет.

## Запуск

Требуется Node.js 22.12+ (проверено на 24.19) и npm.

```sh
npm ci --cache /tmp/discrete-npm-cache
npm run dev
```

Vite сообщает адрес в терминале (порт по умолчанию 5173). Для production:

```sh
npm run build
npm run preview
```

Публикуйте каталог `dist` на статическом хостинге в корне сайта. Для локального режима после загрузки не требуется обращение к внешним сервисам. Вход и синхронизация требуют подключения к вашему Supabase. Первичная загрузка сайта требует доступа к хостингу; service worker для офлайн-запуска не реализован.

## Что есть

- 46 пунктов программы с исходной нумерацией, сгруппированных в 6 тем.
- Поиск по формулировке, номеру и теме; фильтрация по статусу.
- Краткие ответы, объяснения, примеры, доказательства или явно обозначенные планы доказательств. Ссылки на страницы исходного конспекта.
- Скрытые ответы, черновик и самостоятельная оценка. Автоматической проверки нет.
- Статусы «Не изучал», «Изучаю», «Знаю» и список повторения.
- Случайные билеты по выбранным темам, без повторов, с проверкой доступного количества. Раскрытие после завершения и сохранение после оценки всех ответов.
- Прогресс по темам и история билетов с сохранёнными самооценками.

## Замена материалов

Редактируйте `src/data/course.json`, затем пересоберите приложение. Поля:

```json
{
  "title": "Название курса",
  "subtitle": "Подзаголовок",
  "topics": [{ "id": "logic", "title": "Логика", "description": "Краткое описание", "label": "01" }],
  "questions": [{
    "id": "1", "number": 1, "topicId": "logic", "title": "Формулировка вопроса",
    "short": "Краткий ответ с $A\\to B$", "explanation": "Подробное объяснение",
    "example": "Пример", "proof": "Доказательство или явно обозначенный план", "sourcePage": 5
  }],
  "sources": [{"title": "Конспект", "url": "/materials/DMlec-base.pdf"}]
}
```

Формулы заключаются в `$…$`; обратный слеш в JSON удваивается. `id` вопросов должны быть уникальными и стабильными: с ними связан прогресс. `topicId` должен совпадать с существующей темой. Не заполняйте отсутствующие ответы вымышленным текстом: оставьте пустую строку, интерфейс покажет «Ответ нужно добавить» (аналогично для объяснения, примера, доказательства).

Оригиналы вложенных PDF находятся в `public/materials`. Текущий интерфейс и ссылки на страницы рассчитаны на исходные файлы курса; для совершенно другого курса измените также названия курса и ссылки на PDF в `src/main.tsx`. Содержимое PDF использовано как учебные данные, а не как инструкции приложению или разработчику.

## Данные и ограничения

`localStorage`, ключ `discrete-study-v1`, хранит статусы и завершённые билеты. «Знаю» считается изученным вопросом. «Нужно повторить» соответствует «Изучаю» и попадает в повторение; «Не помню» соответствует «Не изучал» и тоже попадает в повторение. Прямая смена статуса обновляет список: «Изучаю» добавляет, два других статуса убирают.

История показывает самооценку на момент сохранения, даже если текущий статус впоследствии изменился. Черновики и незавершённые билеты не сохраняются после перезагрузки. После подключения Supabase доступна синхронизация между устройствами, а в разделе «Синхронизация» — экспорт и импорт резервной копии. Без настройки проекта приложение сохраняет локальный режим. Очистка данных браузера удалит прогресс. При недоступном хранилище приложение продолжает работать и сообщает, что изменения не сохранятся.

Ответы — учебная адаптация конспекта М. Н. Вялого от 19.10.2026. Несколько длинных доказательств даны как планы с отсылкой к PDF. Сохранена нумерация Фибоначчи из конспекта: F₀ = F₁ = 1. В п. 17 отдельно уточнён случай пустой области для тотальной левой обратной.

Билеты учебные: сохранён режим по пунктам программы и добавлен отдельный режим «На доказательство» из лекций, классных и домашних заданий. Это не точная копия официального билета из 3 определений и 3 доказательств с задачами. Оценка из 10 не рассчитывается.

## Проверки

```sh
npm run build
npm test
```

Playwright использует системный `/usr/bin/chromium`, если он доступен, или браузер Playwright. В обычной среде без Chromium предварительно выполните `npx playwright install chromium`. Свой бинарник можно указать через `CHROMIUM_PATH`.

Проверяются поиск, скрытие и раскрытие ответов, сохранение и повторение после перезагрузки, генерация без дубликатов и ошибки нехватки вопросов, самооценки и история билетов, повреждённый и недоступный localStorage, мобильная вёрстка, доступность PDF и все 46 страниц ответов.


## Доказательства и задачи

Раздел «Доказательства» добавлен без замены прежних 46 вопросов. В новой базе 145 карточек: 70 исходных классных задач (71 карточка, поскольку К7.4а и К7.4б* разделены), 25 домашних и 49 нумерованных лекционных утверждений. Подробный [аудит материалов](docs/material-audit.md) содержит таблицу по файлам, классификацию, исключения и все оставшиеся ограничения.

В разделе есть режимы «На доказательство», «Все задания» и «Повторение», поиск по тексту и номеру, фильтры по теме, источнику, типу и статусу. Оригинальный фрагмент условия сохраняет обозначения и подпункты PDF. Идея и решение раскрываются отдельно. Авторские объяснения подписаны и не выдаются за решения преподавателя. У лекционных карточек есть ссылки на доказательства в конспекте; для длинных рассуждений авторский текст может быть только планом.

Материалы редактируются отдельно в `src/data/practice.json`. В каждой карточке:

- `id` — стабильный уникальный идентификатор; `number` — отображаемый исходный номер, `parentNumber` — номер исходной задачи, `part` — выделенный подпункт;
- `source` — `lecture`, `class` или `homework`; `session`, `file`, `page`, `sourceUrl` — происхождение;
- `statement`, `originalImage` и необязательный `originalImages` — текстовая расшифровка и точные фрагменты условия;
- `topicId`, `type`, `proofEligible` — тема, тип и отдельный признак пригодности для доказательства;
- `starred` — звёздочка; исключаются только карточки с `source: "class"` и `starred: true`;
- `outOfScope` — материал вне программы № 1, доступный по отдельному переключателю;
- `reviewNotes` — замечания для сверки, `blocked` — запрет включать неоднозначное условие в билеты;
- `prerequisites`, `idea`, `steps`, `transitions` — определения, идея, шаги решения и ключевые пояснения;
- `solutionOrigin` — `prepared` для авторского решения, `source` для лекционного материала, `missing` при отсутствии надёжного решения. `solutionNote` объясняет происхождение или ограничение; `sourceProofPage` указывает страницу оригинального доказательства.

В билете на доказательство выбираются только `proofEligible`-карточки без необязательных классных звёздочек и без `blocked`. По умолчанию не участвуют темы вне программы и задачи без готового разбора. Отдельный переключатель разрешает включить подходящие задачи без решения, но не добавляет за них выдуманный ответ. Недостаток карточек приводит к сообщению об ошибке; темы не подменяются.

Новые статусы — «Не разбирал», «Разбираю», «Могу доказать самостоятельно», «Нужно повторить». Они и результаты билетов сохраняются отдельно под ключом `discrete-practice-v1`. Основной ключ `discrete-study-v1` не изменён: знание формулировки не приравнивается к умению доказать её. Просмотр решения не меняет статус. После завершения билета оцените каждый материал и сохраните результат; повторение обновится вместе с ним. Незавершённые билеты и черновики после перезагрузки не сохраняются.

Дополнительная проверка источников и формул:

```sh
node scripts/verify-materials.mjs
```

Все исходные PDF сохранены побайтно в `public/materials/sheets`, реестр исходных номеров и SHA-256 — `src/data/material-manifest.json`. При осознанной замене материалов обновите также реестр и ожидаемые количества в тестах. Не изменяйте хеши, чтобы скрыть непреднамеренную замену исходника.

## План подготовки

Раздел «План подготовки» — последовательный маршрут из 12 этапов и 84 пунктов без дат и дедлайнов. Этапы идут от логики и множеств к функциям, индукции, подсчётам, сочетаниям, биномиальным доказательствам, путям, Каталану и включениям-исключениям. Указаны зависимости; знакомые этапы можно открыть без блокировок.

Для каждого этапа есть определения и понятия, доказательства, выбранные конкретные номера классных задач и ДЗ, а также критерий самостоятельного объяснения. Если подходящих задач во вложениях нет (например, незвёздочных задач по Каталану), это отмечено явно. Маршрут покрывает все 46 пунктов программы, но не назначает каждую задачу библиотеки. Необязательные классные со звёздочкой, материалы вне программы № 1, неоднозначные условия и задачи без готового разбора в назначенные пункты не входят.

План вынесен в `src/data/preparation-plan.json`:

- `stages` — упорядоченные этапы с уникальными `id`, заголовком и кратким описанием;
- `dependsOn` — идентификаторы предшествующих этапов, которые нужны для понимания;
- `notes` — оговорки о покрытии и источниках;
- `items` — пункты с уникальным стабильным `id`, текстом `label` и типом `kind`: `learn`, `proof`, `class`, `homework` или `mastery`;
- `targets` — ссылки на существующие материалы: `{ "kind": "theory", "id": "17" }` для основного курса и `{ "kind": "practice", "id": "K3-1" }` для задачи или лекционного утверждения.

Ссылки открывают нужную карточку внутри приложения, сохраняя возможность вернуться к исходному пункту. Галочка относится ко всему пункту: если там несколько материалов, нужно разобрать все перечисленные. «Продолжить» находит первый незавершённый пункт в порядке маршрута, раскрывает нужный этап, прокручивает к пункту и переносит фокус на его чекбокс. Когда всё выполнено, приложение показывает завершение маршрута, не создавая фиктивного следующего шага. Снятие отметки возвращает пункт в маршрут.

Прогресс этапов и всего плана рассчитывается по отмеченным пунктам. Отметки хранятся в `localStorage` под отдельным ключом `discrete-plan-v1`; статусы теории (`discrete-study-v1`) и задач (`discrete-practice-v1`) не изменяются ни просмотром материала из плана, ни галочкой. После возвращения к плану отмечайте пункт самостоятельно. Стабильные `id` позволяют сохранять отметки при дополнении содержания; удалённые пункты не учитываются в прогрессе.

Тесты в `tests/plan.spec.ts` проверяют реальные ссылки и исходные номера, отсутствие запрещённых материалов, порядок зависимостей, покрытие программы, сохранение и снятие галочек, оба уровня прогресса, первый незавершённый пункт, переходы с возвратом, завершённый маршрут, ошибки хранилища и мобильную вёрстку. Эти 24 базовые проверки дополнены проверками облачной синхронизации; текущий полный набор содержит 40 тестов.


## GitHub, сайт и единый прогресс

Все исходники, материалы, план и тесты находятся в репозитории. `.github/workflows/pages.yml` собирает, проверяет и публикует приложение на GitHub Pages после push в `main`; Pages Source нужно один раз установить в **GitHub Actions** в настройках репозитория.

Для общего прогресса на телефоне, планшете и ноутбуке подготовлены Supabase, SQL-миграция с RLS и вход по одному email. Код сам не создаёт чужой облачный проект. Пока URL и публичный ключ не настроены, раздел честно сообщает, что работает только локальное сохранение.

Полная пошаговая инструкция: **[подключить синхронизацию и сайт](docs/sync-setup.md)**.

Кратко: создайте Free-проект Supabase, выполните `supabase/migrations/202610250001_progress_sync.sql`, разрешите адрес сайта для входа, добавьте `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY` в GitHub Actions Variables и запустите workflow. Для локального запуска эти публичные значения задаются в `.env.local` по образцу `.env.example`. Приватные/административные ключи не используются и не должны попадать в приложение.

В разделе «Синхронизация» можно войти по ссылке из письма, затем задать пароль для других устройств. Статусы вопросов и задач, завершённые билеты и галочки плана синхронизируются по отдельным полям с серверными ревизиями. Разные поля объединяются, конфликт одного поля разрешается явно. Сохраняются локальная копия, офлайн-очередь и обратная совместимость с прежними отметками. Импорт добавляет отсутствующие данные без замены уже существующих; экспорт не содержит токенов.

Значение `VITE_BASE_PATH` задаёт базовый путь развёртывания. В GitHub Actions он вычисляется из имени репозитория; локально это `/`. Все ссылки на PDF и изображения учитывают этот путь.
